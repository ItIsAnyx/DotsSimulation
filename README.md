# DotsSimulation

Двухцветный клеточный автомат по мотивам игры «Точки». Первый этап — модель
поля и автономные правила с графическим интерфейсом Tkinter, двумя агентами
и небольшими обучаемыми нейросетями.
Работает на Python 3.10+ без сторонних библиотек. Нужен Python с поддержкой
Tkinter (в обычном установщике Python для Windows — компонент Tcl/Tk).

## Запуск

В PyCharm запустите `main.py` с интерпретатором проекта `.venv`.
Из PowerShell в папке проекта:

```powershell
.\.venv\Scripts\python.exe main.py --seed 42
.\.venv\Scripts\python.exe -m unittest discover -v
```

Размер поля и начальную плотность можно изменить:

```powershell
.\.venv\Scripts\python.exe main.py --width 70 --height 60 --density 0.02
```

По умолчанию открывается окно с полем 30 × 30 и начальной плотностью 0.005.
Насыщенные кружки обозначают точки, светлая заливка — владельца территории.
Поле масштабируется под окно с сохранением квадратной формы клеток.

- «Запуск» / «Пауза» (или пробел) управляют автоматическим обновлением.
- «Фаза →» (или стрелка вправо): один шаг выполняет фазу автомата или
  целый ход одного агента. Цикл: автомат, первый агент, второй агент.
  Первый агент меняется каждый раунд. В режиме «Выключены» шаг выполняет
  только автомат, как раньше.
- «Сначала» возвращает исходное поле и состояние генератора случайных чисел:
  последующие такты повторяются точно.
- Скорость — целевое число тактов в секунду (1–20). На больших полях фактическая
  скорость может быть ниже; интерфейс не накапливает пропущенные такты.
- Размер, плотность и seed применяются кнопкой «Создать поле».
  «Случайный seed» создаёт новое поле с новым seed. Новое поле открывается на паузе.
- В интерфейсе размеры ограничены диапазоном 1–200, плотность — 0–1.
- Сетка отключается флажком и автоматически скрывается на очень мелких клетках.
- Под полем отображаются численность, площадь территории и события последнего такта.
  Курсор показывает координаты и состояние клетки. Поле пока доступно для просмотра.
- Новозахваченные точки и пустые территории отмечены более ярким оттенком цвета
  владельца. Подсветка действует до следующего такта; на паузе и при изменении
  размера окна сохраняется. Рождения точек не считаются захватом.
- «Шанс случайной точки за ход» задаёт вероятность одной попытки рождения
  за такт. «Применить» меняет её без сброса поля; «Создать поле» тоже применяет
  это значение. Например, 0.2 означает 20% шанса на одну новую точку.
- «Шанс растворения» по умолчанию 0.02 на занятую клетку за раунд.
  Он применяется той же кнопкой «Применить». Растворяется только точка
  внутри своей замкнутой территории, окружённая восемью своими клетками.
  Образовавшаяся пустая клетка подсвечивается и никогда снова не становится
  точкой, даже по действию агента. Снятые агентом точки этому запрету не подчиняются.
- Ползунок «Выключить автомат через N ходов» задаёт число первых раундов
  с рождениями, обычной гибелью и случайным перекрашиванием. Снимите флажок
  «Без ограничения», чтобы применить предел. Значение 0 выключает сразу.
  После предела растворение, доход и ходы агентов продолжаются. Настройка
  сохраняется при перезапуске и создании поля; её можно менять во время игры.
  В консоли тот же предел задаёт `--automaton-rounds N`, значение −1 — без ограничения.
- Панели снизу: синие слева, красные справа. Очки — накопленная награда;
  действия — накопленный бюджет; доход — число пустых своих клеток после
  последней фазы автомата. Доход начисляется один раз за раунд.
- «Точки», «Территория» и «Без точек» показывают изменение относительно
  начала текущей/последней фазы: например, `Территория: 170 (+10)`.
  Во время хода агента изменения суммируются по всей фазе, а не только
  последнему действию. На паузе сохраняются; при старте новой фазы отсчёт
  начинается заново. Новое поле и перезапуск показывают нулевые изменения.
- По умолчанию включена **эвристика**: понятные вручную заданные правила.
  В списке доступны отключение агентов, случайные агенты и нейросети.
  Без загруженных весов нейросети не обучены; это указано в интерфейсе.
  Во время просмотра веса не изменяются.
- По умолчанию партия длится 200 раундов, затем победитель определяется
  площадью территории, включая точки. Лимит задаётся `--round-limit`.
  Победа даёт `2 × |очки до финала| + 50`, поражение — отрицательную величину
  по той же формуле со своими очками. Ничья — 0.
- Ход агента состоит из нескольких платных действий до пропуска или исчерпания
  бюджета. Интерфейс выполняет их через очередь событий, чтобы окно отвечало
  на управление. Пауза останавливает переход к следующей фазе; уже начатая
  фаза заканчивается. «Сначала» и создание поля прерывают её и сбрасывают партию.

Консольный режим сохранён:

```powershell
.\.venv\Scripts\python.exe main.py --console --steps 10
.\.venv\Scripts\python.exe main.py --random-birth-chance 0.5
.\.venv\Scripts\python.exe main.py --agents off
.\.venv\Scripts\python.exe main.py --agents neural --model models/selfplay.json
```

В консоли `R` и `B` — точки; `r` и `b` — принадлежащие цвету клетки без точек;
`.` — свободная клетка. Одинаковый seed воспроизводит всю симуляцию.

## Состояние поля

Поле прямоугольное, без замыкания границ. Координаты: `(строка, столбец)`,
индексация от нуля. `Board.points` хранит точки, `Board.owners` — владельцев
территории. Точка всегда принадлежит владельцу своей клетки. Для подготовки
сценария используйте `Board.set_cell`; симуляция копирует переданное поле.

## Один такт

1. По старому полю вычисляются рождение, гибель и перекрашивание.
2. Все локальные изменения применяются одновременно.
3. По полученному полю определяются и одновременно применяются захваты.

Правила задаются неизменяемым объектом `Rules`:

| Параметр | По умолчанию | Смысл |
|---|---:|---|
| `random_birth_chance` | 0.2 | Вероятность рождения одной случайной точки за весь такт |
| `interior_dissolve_chance` | 0.02 | Шанс необратимого превращения внутренней точки в пустую территорию |
| `growth_probability` | 0.12 | Базовая вероятность распространения |
| `diagonal_weight` | 2 | Вес диагонального соседа; прямого — 1 |
| `isolated_death` | 0.35 | Вероятность гибели при отсутствии союзных точек рядом |
| `conversion_probability` | 0.5 | Вероятность перекрашивания при достаточном перевесе |
| `conversion_neighbors` | 3 | Минимальное число атакующих соседей для перекрашивания |
| `capture_enabled` | True | Включение процедуры захвата областей |

Соседство локальных правил — восемь клеток. Для свободной клетки вычисляется
суммарное влияние `W` соседей и вероятность роста `1 - (1 - p)^W`.
При успешном росте цвет выбирается пропорционально влиянию каждого вида.
После локального обновления отдельно проверяется шанс случайного рождения:
не более одной точки за такт, независимо от размера поля. Цвет равновероятный,
место равномерно выбирается среди свободных клеток, которые были свободны
и в начале такта и не заняты локальным ростом. Рождение разрешено только
в клетках без точки и владельца. При отсутствии места попытка пропускается.
Значение 0 отключает случайные рождения; 1 гарантирует попытку каждый такт.
Старое случайное рождение независимо в каждой клетке заменено этим механизмом.

Для существующей точки сначала проверяется перекрашивание: рядом должны быть
минимум три точки противника независимо от количества союзников. При успешном
перекрашивании меняется и владелец клетки. Если перекрашивания не произошло,
изолированная точка может погибнуть. Владение после гибели снимается, если
клетка не остаётся внутри существующего контура. Точки на границе замкнутой
области с хотя бы одной пустой внутренней клеткой защищены от гибели,
но могут быть перекрашены. Сплошной кластер без пустого интерьера защиты
не получает; ответвления снаружи контура также не защищены.

Диагональный приоритет повышает вероятность роста по диагоналям, но не
гарантирует появление ромбов — это предмет дальнейших экспериментов.

## Захват

Для каждого цвета точки этого цвета являются стенами. Обход от границы
по четырём направлениям определяет доступные снаружи клетки. Недоступные
клетки внутри контура становятся территорией цвета; чужие точки внутри
перекрашиваются. Диагональное соприкосновение точек закрывает проход.
Территория без точек стеной не является. Граница поля доступна снаружи,
кроме занятых точками стен: контур может опираться на точки у границы.

Оба набора претензий вычисляются до применения захвата. Если клетку
одновременно окружают оба цвета (например, вложенные контуры), она
не захватывается на этом такте. Каскадных захватов точек в рамках одной фазы нет.
После перекрашивания точек доступность пустых клеток пересчитывается по
полученным контурам: разрушенный контур сразу теряет пустую территорию.
Владение пустыми клетками не сохраняется само по себе. Это исправляет
остающиеся цветные пятна после гибели точек.

Это гибрид локального клеточного автомата с отдельной глобальной процедурой
захвата. Обход использует всё поле, а не только ближайших соседей.

## Интерфейс для следующих этапов

```python
from dots_simulation import Rules, Simulation

simulation = Simulation.random_field(30, 20, density=0.08, seed=42)
events = simulation.step()  # только автономная фаза
print(simulation.board.statistics())
```

`StepResult` содержит координаты подсветки `highlighted_cells` и
`highlighted_points`, а также число рождений, смертей, локальных перекрашиваний,
смен владельца при захвате и перекрашенных при захвате точек. Последние два
счётчика могут включать одну клетку; это разные события, а не готовая награда.
`statistics()` возвращает число точек, всей территории (включая точки)
и территории без точек для каждого цвета.

Фазы, бюджет и награды реализованы в `dots_simulation/game.py`. Методы
`legal_actions()` и `apply_action()` проверяют ходы агента. `set_cell`
предназначен для редактирования сценариев, а не для ходов игроков.

## Нейросети и обучение

Подробное объяснение решений, формул и ограничений: [docs/RL_GUIDE.md](docs/RL_GUIDE.md).

Агент может поставить точку в любой свободной нейтральной клетке за 1 действие,
без союзных соседей. Первый захват нейтральной клетки (точкой или окружением)
даёт +5, как захват вражеской клетки. Свою пустую клетку можно заполнить за 1
без награды. Цена перекрашивания чужой точки — 3, нужны три союзных соседа.
Повторное освоение одной и той же нейтральной координаты не приносит новый бонус.

При обучении и контрольной оценке полный автомат работает первые 8 раундов.
Затем остаются растворение и доход. Значения по умолчанию: `--automaton-rounds 8`
и `--dissolve-chance 0.02`. Поиск по-прежнему не участвует в обучении.
Для эксперимента на новых правилах сохраните отдельную модель:

```powershell
.\.venv\Scripts\python.exe train.py --episodes 100 --rounds 80 --width 30 --height 30 --output models/selfplay_v4.json
.\.venv\Scripts\python.exe main.py --agents search --model models/selfplay_v4.json --automaton-rounds 8
```

CSV дополнительно содержит `neutral_placements`, `full_automaton_rounds`
и `maintenance_rounds`: можно проверить самостоятельное освоение поля и
точное число фаз до/после отключения. Изменение среды не гарантирует роста силы;
старые модели обучены на других правилах, хотя формат весов совместим.

У каждого цвета собственная политика 333 → 16 → 1 и отдельная сеть оценки
позиции той же формы. Наблюдение содержит прежние 20 показателей, расположение
клеток в окне 9 × 9 вокруг кандидата, обзор всего поля в сетке 4 × 4 и шесть
дополнительных показателей. Обе сети учатся только на обычных партиях self-play.
По умолчанию пропуск разрешён: нет принудительного наступления или шаблона
«отрезать выступ». Сеть оценки учит будущую суммарную награду по результатам партий.
Для скорости на каждом решении выбирается до 64 случайных кандидатов каждого
типа; выборка обновляется после каждого действия. Все ходы проходят проверку.

Учебная награда теперь равна разнице изменений очков игроков. Показатели
на панели остаются индивидуальными очками. `gamma` по умолчанию 0.995
применяется за раунд, а не за каждое платное действие. В CSV добавлены расходы
бюджета, остатки бюджета, ранние пропуски и захваты, оставшиеся при пропуске.
На панели видно, сколько очков действий потрачено в текущем раунде.

Старые JSON загружаются, но помечаются как требующие переобучения.
Их несовместимая baseline сбрасывается. Для чистого эксперимента сохраните
старую модель и обучите новую с нуля (новые входы старых весов дополняются нулями):

```powershell
.\.venv\Scripts\python.exe train.py --episodes 100 --rounds 80 --width 30 --height 30 --output models/selfplay_v3.json
.\.venv\Scripts\python.exe main.py --agents search --model models/selfplay_v3.json
```

Режим «Нейросеть + поиск» проверяет цепочки на копиях игры: по умолчанию глубина
4 действия, луч 4 продолжения, до 5 ветвей из каждой позиции и до 100 проверенных
переходов на решение. Ранжирование — фактическая учебная награда плюс оценка
конечной позиции сетью. Предложения — вероятные ходы политики и случайные
альтернативы; пропуск тоже проверяется. Выполняется первый ход лучшей найденной
цепочки, затем поиск повторяется. Соперник и автомат внутри цепочки не моделируются.
Это ограниченный поиск, а не доказательство оптимальности. В GUI веса заморожены.
Обычный режим «Нейросеть» позволяет сравнить ту же модель без поиска.

Параметры поиска можно задать при запуске GUI или консоли:

```powershell
.\.venv\Scripts\python.exe main.py --agents search --model models/selfplay_v3.json --search-depth 5 --search-beam 5 --search-branches 5 --search-nodes 150
```

Поиск не используется в `train.py` и не обучает сеть повторять найденные цепочки.
Флаг `--legacy-active` явно включает прежний тактический запрет пропуска для
сравнения. `--allow-early-pass` сохранён для совместимости; теперь это стандартный режим.
100 партий — начальный эксперимент, а не гарантия сильного игрока.

Обучение REINFORCE реализовано на чистом Python. Установка PyTorch или NumPy
не требуется. Это небольшой учебный вариант, а не готовый сильный игрок.

```powershell
.\.venv\Scripts\python.exe train.py --episodes 100 --rounds 80 --output models/selfplay.json
.\.venv\Scripts\python.exe main.py --model models/selfplay.json
```

Можно загрузить JSON кнопкой «Загрузить веса…» без перезапуска окна.
В `train.py` изначально используется поле 16 × 16 для скорости экспериментов;
сеть поддерживает и другие размеры, но перенос качества на большие поля
не гарантируется. CSV рядом с JSON содержит награды, победителя, число
действий по типам, число решений с реальным выбором и нормы градиентов.
До и после обучения проводится сравнение с эвристикой на отдельных seed,
за оба цвета. Нескольких контрольных партий недостаточно для вывода о силе.
`--eval-games 20` задаёт 20 seed, то есть 40 контрольных партий.

```powershell
.\.venv\Scripts\python.exe train.py --resume models/selfplay.json --episodes 100 --output models/continued.json
```

Продолжение загружает веса и базовую оценку наград, использует следующие
seed по счётчику партий. Это новый запуск обучения, а не точное восстановление
незавершённой партии. JSON обновляется после каждой завершённой партии;
CSV содержит партии текущего запуска.
